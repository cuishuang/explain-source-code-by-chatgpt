# File: fd_poll_runtime.go

fd_poll_runtime.go文件的作用是实现了在Go语言中使用系统调用epoll来进行I/O事件轮询。在Linux系统中，epoll是一种高效的I/O事件通知机制，可以帮助Go语言程序实现高并发、高性能的I/O操作。

fd_poll_runtime.go文件实现了一个被称为“fd_poll_runtime”的结构体，该结构体封装了epoll相关的数据和方法。fd_poll_runtime中的方法包括：

- Init：初始化一个epoll描述符，并将其与一个文件描述符进行绑定。
- Close：关闭epoll描述符。
- AddFD：向epoll描述符中添加一个新的文件描述符，并设置相应的事件监听器。
- DelFD：从epoll描述符中删除一个文件描述符。
- Poll：进行I/O事件轮询，当有事件发生时，调用相应的处理函数。

在Go语言中，文件描述符是唯一的I/O操作的标识符，通过fd_poll_runtime.go文件中实现的fd_poll_runtime结构体可以轻松地实现对文件描述符的I/O事件监听和处理。

### pollDesc

pollDesc是Go语言实现的一个与操作系统文件描述符相关的结构体，它封装了一个文件描述符和与该文件描述符关联的I/O事件。

具体来说，pollDesc结构体中包含以下重要字段：

- fd：文件描述符，它是pollDesc结构体与操作系统文件描述符之间的中介。

- closing：表示文件描述符是否正在被关闭。

- rd/wr/er：分别表示文件描述符上的读、写、错误事件。

- ri/wi：分别表示是否已经准备好读和写。

- wd：表示文件描述符是否是一个监听套接字。

- user：与此文件描述符关联的用户数据。

通过这些字段，pollDesc结构体可以对文件描述符上发生的各种事件进行管理和处理，同时也提供了一些方法供调用者进行操作，例如：

- Ready：获取当前文件描述符上已经准备好的I/O事件类型。

- Wait：等待文件描述符上的I/O事件，直到超时或有事件发生。

- Close：关闭文件描述符。

- Evict：从调度器中移除此文件描述符。

总的来说，pollDesc结构体是Go语言实现的I/O复用的核心结构体之一，它能够有效地管理文件描述符上的I/O事件，提高程序性能和可维护性。

### runtime_pollWait

在Go语言的实现中，内核通过文件描述符（file descriptor，简称fd）来管理文件、套接字等资源。而在读写文件或套接字时，是通过内核提供的系统调用来完成的，这些系统调用中最常用的是read、write、recv、send等。当应用程序调用这些系统调用时，内核将会在一个特殊的位置（称为fd table）中寻找该文件描述符对应的资源，并执行相应的操作。

然而这些系统调用都是阻塞式的，也就是说，如果应用程序调用了read或recv等系统调用，在没有读取到数据时，程序会一直等待，直到有数据到来或者超时。在这个等待过程中，应用程序会被阻塞，这会导致应用程序的性能变得十分低下。而且，由于在Linux下使用file descriptor作为IO接口的显式方式不便于并行化，所以Go语言会通过内部实现来提高性能。

在go/src/internal/fd目录下，实现了Go语言自己的fd实现，将fd包装成了文件对象，并提供了一种非阻塞式的IO方式，这使得Go语言的网络编程和文件操作都变得十分高效。

在这个包中，fd_poll_runtime.go文件中的runtime_pollWait函数的作用是等待从内核异步IO events，如果events地址非空，该函数会将已经准备好的事件数量存放到events中。如果发现已经准备好的事件数量大于等于0，则该函数返回true。如果指定的时间段内没有发现任何准备好的事件，则该函数返回false。

具体实现中，runtime_pollWait函数会首先检查pollDesc对象是否被关闭（可通过runtime_pollClose函数关闭）。如果pollDesc已经被关闭，则函数直接返回。否则，该函数会调用runtime_pollWait函数来等待内核事件，并等待指定的时间段或者有事件发生时立即返回。如果等待时间超时，则函数返回false；如果等待期间有事件发生，则将该事件数量存入events中，并返回true。

runtime_pollWait函数的作用是通过轮询方式实现异步IO事件的处理，并且避免了应用程序在等待IO事件时的阻塞，这也就提高了应用程序的性能。

总之，`runtime_pollSetDeadline`的作用是为文件描述符设置超时时间，从而实现I/O操作的超时控制。



### runtime_pollUnblock

在 Go 语言中，当使用标准库进行网络 I/O 操作时，底层会调用操作系统提供的 I/O 多路复用机制进行事件等待，并使用 `runtime_poll` 包来与操作系统进行交互。这个过程中，如果某个 I/O 事件长时间未能就绪（比如网络连接超时），则当前协程会被阻塞，无法继续执行。如果此时其他协程中有任务需要调度，则会造成资源浪费。

为了解决这个问题，Go 语言提供了一种机制：非阻塞 I/O 等待（Non-Blocking I/O）。它的实现方式是使用 `runtime_pollUnblock` 函数主动唤醒被阻塞的协程，使其能够继续执行。具体来说，`runtime_pollUnblock` 函数会将一个阻塞在 I/O 事件上的协程的状态设置为“就绪”，并将其加入到可运行队列中，等待调度器调度。

值得注意的是，`runtime_pollUnblock` 函数需要在一个操作系统线程（OS thread）上执行。这就意味着，如果当前线程没有足够的空闲时间去处理唤醒请求，那么该请求可能会延迟执行，影响程序的性能。为了避免这种情况，Go 语言使用了一种叫做“M:N 调度”的机制，将多个协程绑定到少量的线程上，使得系统能够更高效地利用资源。

### close

在Go语言中，每个 OS Level 的 File Descriptor 都需要分配一个 fdPoll 结构体以进行异步 I/O 操作和事件轮询。fdPoll 结构体包含一组众所周知的等待事件的goroutine等待信号，以及实现最终取消等待的机制。

close 函数是在 fdPoll 结构体完成它的任务后被调用的，用于关闭当前的 File Descriptor。在这个函数中，首先会取消可能存在的等待事件，然后清空等待队列并关闭底层的 File Descriptor。最后，将 fdPoll 结构体从内存中删除，并释放其中分配的资源。

具体来说，该函数会执行以下操作:

1. 获取 fdPoll 的状态
2. 如果状态是 waiting，说明 fdPoll 此时在等待通知:
  2.1 若正在等待，则用等待中的 goroutine 执行 ready()/disable() 操作去取消等待。
  2.2 跳过。
3. 如果状态是 disabled，说明 fdPoll 已经被停用了，因此直接跳过。
4. 将 fdPoll 的状态设置为 closed。
5. 关闭该 fdPoll 的文件描述符。
6. 从全局映射表中移除该 fd 所对应的 fdPoll 结构体。
7. 释放当前 fdPoll 结构体占用的资源。
8. 将 fdPoll 从等待事件队列中移除。

close 函数实现了清理操作和资源释放的功能，确保所有底层的文件描述符都可以被正常关闭，从而避免出现因为资源泄露而导致的异常情况。

### wait

wait函数是一个关键的系统调用函数，在 Go 运行时中，它主要用于等待指定数量的文件描述符中的某一个或多个就绪，并返回它们的状态信息。wait 函数是基于 select 模型实现的，其主要目的是让 Go 应用程序能够异步地等待多个文件描述符的状态变化，而不会阻塞整个程序。

1. WaitRead：表示等待列表中的文件描述符中至少有一个可读。

3. WaitError：表示等待列表中的文件描述符中至少有一个出错或被关闭。

wait 函数的内部实现是调用了内核级别的 epoll_select 等系统调用函数，以实现高效地等待文件描述符的就绪状态。在等待过程中，wait 函数还会持续地监听操作系统事件，以确保在有任何文件描述符就绪时都能及时返回其就绪状态信息。

总的来说，wait 函数在 Go 运行时中扮演着重要的角色，可以帮助 Go 应用程序异步等待多个文件描述符的状态变化，从而提高整个程序的性能和响应速度。



### waitRead

waitRead函数是在fdPoller中等待读取事件的函数。

它会执行以下步骤：
1. 定义事件event并初始化为0。
2. 将当前的readBufs转换成pollDesc对象，并把pollDesc对象加入到fdPoller.pollDescs slice中。
3. 调用fdPoller.Poll()函数，等待读取事件，该函数会阻塞直到等到事件或发生错误。
4. 如果pollErr不是nil，表明等待过程中出错，此时会将pollDesc对象从pollDescs slice中删除，并返回pollErr。
5. 如果注册的事件中包含了read事件，则设置event为epollIN。
6. 如果event为0，则表示没有收到需要处理的事件，此时需要将pollDesc对象从pollDescs slice中删除，并返回nil。
7. 如果已经收到读取事件，则将pollDesc对象从pollDescs slice中删除，并返回nil。

waitRead函数的作用是等待读取事件并返回对应的pollDesc对象。它是在等待IO事件的过程中调用的，可以帮助Go程序实现高效的IO操作。



### waitWrite

总的来说，waitWrite函数是实现非阻塞式文件操作的重要工具，在内部实现中起到了关键作用。

### IsPollDescriptor

IsPollDescriptor是一个计算机函数，它位于Go语言标准库中的fd_poll_runtime.go文件中。该函数主要用于检查给定的文件描述符是否支持多路复用（即它是否可以被传递给poll或epoll等系统调用）。为了理解该函数的作用，需要先介绍一些背景知识。

在Unix-like系统中，文件描述符是一种用于访问文件、网络套接字等I/O资源的抽象概念。每个进程都有一个文件描述符表，其中包含了所有它当前打开的文件描述符。当执行一个I/O操作时，进程会将所需的文件描述符传递给操作系统内核，以便内核可以执行该操作。例如，使用系统调用read从文件读取数据时，需要将待读取文件的文件描述符传递给内核。

多路复用是一种高效的I/O编程技术，它允许一个进程同时监听多个文件描述符的I/O事件（例如可读、可写等）。通过使用多路复用，可以将多个I/O操作合并到一个系统调用中，以提高进程对I/O事件的响应速度。常见的多路复用技术包括select、poll和epoll等。

在Go语言中，使用运行时库实现了一个基于epoll系统调用的网络事件驱动模型，称为Goroutine Poller。它允许一个goroutine同时监视多个网络连接的I/O事件，以此实现高效的并发网络编程。而IsPollDescriptor函数就是Goroutine Poller中的一个重要组成部分。它的作用是判断给定的文件描述符是否可以作为Goroutine Poller的输入。如果是，则返回true；否则返回false。

IsPollDescriptor函数的实现基于当前操作系统环境和运行时配置。不同的操作系统和运行时版本可能会有不同的实现方式。根据当前操作系统是否支持EPOLLRDHUP选项和是否为文件描述符打开触发EPOLLERR事件的标记等条件，IsPollDescriptor函数会返回不同的值。通过这种方式，IsPollDescriptor可以确保只有支持多路复用的文件描述符被递交给Goroutine Poller处理，从而保证了系统性能和稳定性。
